# الداشبورد — لوحة إدارة المنتجات

## التشغيل
```bash
cd dashboard
npm install        # أول مرة بس
npm run build      # بعد أي تعديل في web/src
npm start          # → http://localhost:5178
```
للتطوير: `npm run dev` (Vite على 5179 مع hot reload، والـ API على 5178).

## الفكرة
- **مفيش database.** السيرفر (`server/index.mjs`، Node بدون مكتبات) بيقرا `campaigns/` و `Books/` مباشرة كل مرة، وبيبعت تحديث لايف (SSE) لما أي ملف يتغير. يعني أي حاجة Claude أو الـ Skills يحفظوها تظهر لوحدها.
- **مفيش أسماء كتب في الكود.** أي فولدر في `campaigns/` بيظهر كمنتج، ولو مفيش `product.json` البيانات بتتستنتج من اسم الفولدر.
- **المراحل من `pipeline.config.json`** في روت البروجكت. أي مرحلة أو Skill أو نوع منتج جديد يتضاف هناك.

## عقد المنتج — `campaigns/<slug>/product.json`
```json
{
  "slug": "شفرة-الرجالة",
  "name": "شفرة الرجالة",
  "type": "ebook",
  "status": "active",
  "series": "الشفرة",
  "source": "Books/2- شفرة الرجالة",
  "mainFile": "Books/2- شفرة الرجالة/كتاب شفرة الرجالة.pdf",
  "created": "2026-11-23",
  "notes": "",
  "stages": { "research": { "status": "review", "note": "...", "updatedAt": "2026-11-23" } }
}
```
- `type`: مفتاح من `productTypes` في `pipeline.config.json`.
- `status`: `planned` | `active` | `paused` | `archived`.
- `stages.<id>.status` (يدوي، اختياري): `in-progress` | `review` | `approved` | `needs-fix` | `rejected` | `skipped`.
  - الحالة اليدوية بتغلب على التلقائية.
  - الحالة التلقائية بتتحسب من الملفات: `missing` (لسه)، `partial` (فيه ملفات بس الناتج القياسي ناقص)، `done` (موجود)، `blocked` (مستني مرحلة قبله).

## التعديل من الداشبورد (المرحلة 2)
- **تعديل الملفات**:
  - أي Markdown أو JSON أو TXT له محرر بثلاث أوضاع: تعديل، وجنب بعض، ومعاينة. الحفظ بـ Ctrl+S.
  - أي CSV بيتعدّل كجدول، تقدر تزوّد فيه صفوف أو تمسح.
- **خطة المحتوى**: تعديل `calendar.csv` بيتنقل تلقائي لـ `calendar.md`، والخانات اللي اتغيرت بس هي اللي بتتعدل. الأيام الجديدة بتتضاف في جدول الأسبوع بتاعها. نفس الكلام لما تسترجع نسخة قديمة من الـ CSV.
- **التعارض**: لو الملف اتغير على الديسك (من Claude مثلًا) وإنت بتعدّل، بيظهر تنبيه. تختار تاخد النسخة الجديدة، أو تحفظ تعديلاتك فوقها. والسيرفر نفسه بيرفض الحفظ فوق نسخة إنت مشفتهاش (409).
- **السجل**:
  - كل حفظ أو رفع أو حذف أو تغيير حالة بيتعمل له commit لوحده، باسم المسار.
  - من «السجل» في أي ملف تقدر تشوف النسخ القديمة وترجع لأي واحدة منها.
  - الميديا التقيلة (mp4/mp3) مستبعدة من git، فملهاش سجل.
- **الحذف**: مفيش حذف نهائي. الملف بيتنقل لـ `.trash/<التاريخ>/<المسار>` في روت البروجكت.
- **الرفع**:
  - في كل مرحلة تقدر تسحب الملفات أو تختارها، وتحدد الفولدر الفرعي أو تعمل فولدر جديد.
  - من يوم في خطة المحتوى، التصميم بيترفع على `02-visuals/week-N/day-N-<وصف>/`، وزرار «اكتبه بنفسك» بيعمل `01-copy/week-N/day-N-<وصف>.md` بنفس الاسم.
- **المراجعة**:
  - حالة يدوية لكل مرحلة: شغال، أو مستني QA، أو معتمد، أو محتاج تعديل، أو محتاج إعادة، أو مش مطلوب. ومعاها ملاحظة.
  - ولكل ملف مراجعة: معتمد، أو محتاج تعديل، أو محتاج إعادة. ومعاها ملاحظة.
  - الاتنين بيتحفظوا في `product.json`: الأولى تحت `stages`، والتانية تحت `reviews`.
- **بيانات المنتج**: الاسم، والحالة، والسلسلة، والنوع، والملف الأساسي، والملاحظات بتتعدل من «نظرة عامة». الـ slug نفسه مبيتغيرش.
- **منتج جديد**: زرار «+ منتج جديد» في الصفحة الرئيسية، وبيعمل نفس اللي بيعمله السكريبت.

### الحماية
- السيرفر بيسمع على `127.0.0.1` بس.
- أي طلب كتابة لازم فيه هيدر `X-Dashboard: 1`. ده بيمنع أي موقع تاني مفتوح في المتصفح إنه يكتب على ملفاتك.
- الكتابة مسموحة جوه `campaigns/` و `Books/` بس.

### مراقبة الملفات
السيرفر بيعمل watcher لكل فولدر لوحده، مش watcher واحد recursive. السبب إن الـ recursive بتاع Node على Linux بيفقد الملف لما يتستبدل بـ rename، وده بيحصل في الحفظ الذري، فالداشبورد كان هيبطّل يشوف تعديلات Claude بعد أول حفظ.

## تشغيل الـ Skills من الداشبورد (المرحلة 3)
في كل مرحلة فيه لوحة «تشغيل بـ Claude» فيها تلات أزرار:
- **▶ شغّل**: بيشغّل الـ Skill بتاعة المرحلة على المنتج. المراحل اللي بتشتغل بالأيام (البوستات، والتصاميم، والريلز) بتطلب الأيام (مثال: `6-10, 12`)، والخانة بتتملي لوحدها بأول أيام ناقصة.
- **✎ عدّل حسب الملاحظات**: بيبعت للـ Skill ملاحظات المراجعة اللي على ملفات المرحلة وملاحظة المرحلة نفسها، عشان تعدّل نفس الملفات.
- **✓ مراجعة QA**: بيشغّل `content-qa-reviewer`، من غير أي صلاحية كتابة.

**إيه اللي بيحصل في كل مهمة:**
1. المهمة بتدخل طابور. الحد الأقصى `runner.maxConcurrent` مهمة في نفس الوقت، ومهمة واحدة بس لكل منتج.
2. السيرفر بيشغّل `claude -p` في روت البروجكت (`--output-format stream-json`)، بالبرومبت ده:
   - برومبت المرحلة من `pipeline.config.json`.
   - بيانات المنتج.
   - تعليماتك الإضافية.
   - system prompt بيمنع الأسئلة، ويمنع تعديل `product.json`، ويمنع الـ commit.
3. السجل بيظهر لايف في صفحة المهمة: كلام Claude، والأدوات اللي استخدمها، والأخطاء.
4. لما تخلص:
   - الملفات اللي اتغيرت بتتعرض.
   - بيتعمل لها commit واحد باسم المهمة.
   - المرحلة بتتعلّم «مستني QA».
   - ولو `runner.autoQa` شغال، مراجعة QA بتبدأ لوحدها.
5. حكم QA (✅ أو ⚠️ أو ❌) بيتسجل على حالة المرحلة (معتمد، أو محتاج تعديل، أو محتاج إعادة)، ومعاه ملخص الملاحظات.
6. **رسالة متابعة**: بتكمّل نفس المحادثة (`--resume`). مثلًا: «خلّي الهوك أقصر».
7. **الإيقاف**: الملفات اللي اتعملت لحد وقت الإيقاف بتفضل، والمرحلة بترجع لحالتها اللي كانت عليها. ولو السيرفر نفسه اتقفل، أي `claude` شغال بيتوقف معاه.

**الصلاحيات** (في `pipeline.config.json` ← `runner`):
- الافتراضي: `acceptEdits`، والأدوات المسموحة `Read Write Edit Glob Grep Skill TodoWrite` بس.
- أي `Bash` لازم يتضاف صريح للمرحلة اللي محتاجاه في `extraTools` (الريلز مثلًا عندها `npx remotion`).
- لكل مرحلة ميزانية دولارات (`budgetUsd`)، والمهمة بتقف لو وصلتلها.
- QA بيشتغل بأدوات قراءة بس.

**المتطلبات**: الـ `claude` CLI متسطب ومسجّل دخول. لو مش مسجّل، الأزرار بتتقفل ويظهر تنبيه. التسجيل مرة واحدة من Terminal:
```bash
claude
```
وجوه الجلسة اكتب `/login`.

**ملفات المهام**: كلها في `.jobs/` في روت البروجكت، ومستبعدة من git:
- `<id>.json`: البيانات.
- `<id>.jsonl`: السجل.
- `<id>.prompt.md`: البرومبت اللي اتبعت.
- `<id>.report.md`: تقرير QA.

**للاختبار من غير Claude حقيقي**: `CLAUDE_BIN=/path/to/stub npm start`. أي برنامج بيطلّع نفس شكل الـ stream-json بينفع.

## منتج جديد
```bash
node dashboard/scripts/new-product.mjs --name "اسم الكتاب" --series "السلسلة"
node dashboard/scripts/new-product.mjs --scan    # يسجّل أي فولدر في campaigns/ أو Books/ ملوش product.json
```

## أنواع المراحل في `pipeline.config.json`
- `single`: ملف ناتج واحد أو أكتر (`outputs`). موجود لما كلهم يكونوا موجودين.
- `perDay`: بيتربط بأيام `00-calendar/calendar.csv`، وملفاته فيها `day-<N>` في الاسم. `match: "file"` للبوستات، و`"folder"` لفولدرات التصاميم.
- `collection`: فولدرات عناصر (زي الريلز). موجودة لما يبقى فيها ميديا.

## الملفات
- `lib/core.mjs`: اكتشاف المنتجات، وحساب حالة المراحل، وربط الأيام، والبحث.
- `server/index.mjs`: الـ API للقراءة (`/api/products`، و`/api/products/:slug`، و`/api/file`، و`/api/search`، و`/api/events`).
- `server/write-routes.mjs`: الـ API للكتابة (`/api/save`، و`/api/upload`، و`/api/new-file`، و`/api/trash`، و`/api/restore`، و`/api/history`، و`/api/version`، و`/api/products/:slug/{meta,stage,review}`).
- `lib/write.mjs`: كل عمليات الكتابة، ومزامنة `calendar.md`، وإنشاء منتج جديد.
- `lib/git.mjs`: الـ commit لكل تعديل، والسجل، والنسخ القديمة.
- `lib/jobs.mjs`: طابور المهام، وتشغيل `claude -p`، وقراءة الـ stream، والـ QA، وحالة المراحل.
- `web/src/Jobs.tsx`: لوحة التشغيل، وقايمة المهام، وصفحة السجل اللايف.
- `web/src/Edit.tsx`: المحررات، والسجل، والمراجعة، والرفع، وحالة المرحلة، والفورمات.
- `web/src/`: الواجهة.
  - `Home.tsx`: كروت أو مصفوفة كل المنتجات.
  - `Product.tsx`: صفحة المنتج بمراحله.
  - `ui.tsx`: عارض الملفات.
